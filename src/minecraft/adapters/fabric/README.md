# Fabric bridge, protocol version 2

`FabricAdapter` controls the player already logged into the Fabric Minecraft client. It does not log in another bot account. The Node service listens only at `ws://127.0.0.1:8765/astra` (configurable port). Java authenticates using `Authorization: Bearer <64-hex-character pairing token>`. Exact Host checks, rejection of browser Origin headers, one-client admission, a 512 KiB message cap, and validated snapshots restrict access to the local mod. The pairing token is not an OpenAI API key and must not be shared.

The client sends `hello` with protocolVersion 2, username, a unique sessionId for this connection/world, a stable worldId, controlsEnabled, a monotonically increasing controlEpoch, supportedActions, and optional capabilities. Node replies `welcome` and sends a heartbeat every second. An updated mod advertises capability `unrestricted-v1`; only local `FABRIC_UNRESTRICTED=true` enables that mode. Its session-addressed `welcome` contains `unrestricted: true`. A capability announcement alone cannot enable it, and a backend configured for unrestricted mode rejects actions from an old mod with an update-mod message. The client sends a complete WorldState in `state` at least every 500 ms. The adapter considers the player connected only while the snapshot is less than three seconds old; stale sessions are closed and outstanding actions cancelled. Cached snapshots are cloned when returned to callers. The wire serverId is replaced with the profile ID and a hash of worldId so memories and coordinates stay isolated between worlds.

Each action carries requestId, sessionId, controlEpoch, action, arguments, and timeoutMs. In bounded mode timeoutMs is 100–60000. In unrestricted mode the default is 0, meaning no action deadline and no Node timer, while an explicitly requested positive timeout remains meaningful. Finite durations are limited only by the timer representation (2147483647 ms). Responses must match the active session and a pending request. Late responses cannot complete another command. Only the semantic actions advertised by the mod and allowlisted in `protocol.ts` can run; unsupported actions fail explicitly. Control requests use `control_player`; unrestricted `walk` supports `duration_ms: 0` to continue until stopped or replaced. A positive walk duration still ends after that duration. Continuing walk and follow acknowledge `data.started: true, data.untilStopped: true` before completion. Follow has no 60-second cap in this mode and waits if the named player is not loaded, reacquiring them when visible to the client. Other arguments use the existing tool names and snake_case argument fields.

The mod must start disarmed, release all synthetic inputs on disconnect, heartbeat loss, leaving a world, or emergency stop, and increment controlEpoch whenever control changes. Node rejects ordinary actions while disarmed. `cancel`, `stop_following`, and `control_player` with `command: "stop"` remain available for safety; stop action results still require a client acknowledgement. A `control` packet with enabled=false cancels pending requests and emits CONTROL_DISABLED. A world exit uses `session_end`; a rejoin requires another hello. SERVER_DISCONNECTED events are intentional: the same local listener stays available for the mod to rejoin instead of starting duplicate servers.

Unrestricted mode removes automatic disarming on manual input or focus loss, and removes the controller's 64-block movement cap, conservative obstacle/fluid/drop veto, and stuck timer. It uses ordinary walking and jumping, not teleportation or a new full pathfinder: walls and unloaded targets can still prevent progress, and walking into hazards can kill the player. Menus temporarily suspend synthetic inputs and defer actions without disarming; closing the menu resumes the action. Local F8/F9, explicit backend cancellation, death/spectator mode, world changes, and connection failures still clean up input ownership. Authentication, session validation, profile permissions, valid game reach/visibility, and bounded message/queue memory remain intact. Replacing an action cancels the previous action; completing finite requested work does not make it repeat forever.

There is no shell execution, arbitrary packet API, arbitrary server-command transport, or filesystem API on this bridge. Plain Minecraft chat cannot contain slash commands or newlines. Server-profile combat, block-breaking, and placement restrictions also apply; disabling placement disables generic right-click/use because that may place a held block.

Tests use a local mock WebSocket client and no Minecraft or OpenAI calls. Passing them verifies the controller contract, not a live Minecraft play session.
